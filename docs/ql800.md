These are the original hardware investigation notes. The current native Rust driver is in `server/src/printer.rs`; use [STUDIO.md](../STUDIO.md) for installation.
Checked 2026-09-28. These findings distinguish what the printer documentation establishes from what has actually been verified on `labels.local`. The initial research was followed by the status-only query documented below. No label was printed.

## Linux implementation update

The later investigation found community protocol research for QL-700, then verified the same auto-power-off read/write exchange on our QL-800. See [Linux utility and evidence](linux-power-settings.md). Its setting now reads 0 after previously reading 6. Long-idle behavior and power-cycle persistence remain unverified. The following sections preserve the earlier documented-vendor-path findings.

## Power behavior

Brother identifies **Auto Power Off** as the setting that turns the QL-800 off after an idle period. Its [QL-800 FAQ](https://support.brother.com/g/b/faqend.aspx?c=us_ot&faqid=faqp00001613_001&lang=en&prod=lpql800eus) instructs connecting the printer by USB to a Windows or Mac computer and setting **Auto Power Off (AC/DC)** to **None** in the Printer Setting Tool. The Li-ion setting in that FAQ applies only to QL-810W/820NWB. Brother's [Mac tool guide](https://support.brother.com/g/b/sp/faqend.aspx?c=sg&faqid=faqp00100080_002&lang=en&prod=lpql800eas) says its QL-800 AC setting offers None or 10–60 minutes, that **Current Settings** reads existing settings, and that settings should be applied only while the printer is in standby. It also describes **Auto Power On** as power-up when the AC cord is plugged in; that is a different setting from preventing idle shutdown. Brother [notes a delay after reconnecting AC power](https://support.brother.com/g/b/sp/faqend.aspx?c=as_ot&faqid=faqp00100577_000&lang=en&prod=lpql800eas), even when Auto Power On is enabled.

The official [QL-800 raster command reference](https://download.brother.com/welcome/docp100278/cv_ql800_eng_raster_101.pdf) documents a 32-byte status reply to `ESC i S` and print control commands, but lists no command to read or change the persistent Auto Power Off setting. The status request reports printer/media/error state, not the configured idle timeout. **No documented Linux power-setting operation was found.** Do not infer that a status query, print job, USB reset, or software “wake” will change the power setting or turn on a powered-off QL-800. The concrete fix is to inspect the current setting and apply `None` with Brother's Printer Setting Tool over USB, then verify after an idle interval. That action remains outstanding.

## Observed Pi state

Read-only SSH checks found a Raspberry Pi 3 running Python 3.11.2, an active `brother_ql_web.service`, and a connected `04f9:209b Brother Industries, Ltd QL-800 Label Printer` at `/dev/usb/lp0` (`root:lp`, mode `0660`). The service runs `/opt/brother_ql_web/.venv/bin/python`; that environment has `brother-ql==0.9.4` and `pyusb==1.2.1`. The system Python does not contain `brother_ql`. USB enumeration establishes that the printer is connected and powered at the time of the check; it does not establish a successful print, loaded media, current Auto Power Off value, or whether the old app can communicate with it. The subsequent status query is documented below.

## Modern raster backend

The proposed [brother_ql-inventree 1.3](https://pypi.org/project/brother-ql-inventree/) is a maintained fork of `brother-ql`, published as a platform-independent Python 3 wheel. The [project's verified-model list](https://github.com/matmair/brother_ql-inventree) includes QL-800 and lists `62red` as a 696-pixel printable-width, 62 mm continuous roll. Its README currently says the fork is in maintenance mode; it is a compatibility update, not an actively expanding driver. The Python implementation pinned version 1.3, and its `app/labeldesigner/printer.py` used its `brother_ql` import namespace, `linux_kernel` backend for `/dev/usb/lp*`, status helper, and `dpi_600` option. The package's universal wheel is encouraging for 32-bit Raspberry Pi OS, and the complete production dependency set has since been installed on the Pi. The deployed application successfully retrieves physical USB status. Print quality and optional hardware modes still need user validation.

Brother's [raster reference](https://download.brother.com/welcome/docp100278/cv_ql800_eng_raster_101.pdf) defines 300 dpi across the tape and either 300 or 600 dpi in the feed direction. The 600 dpi option is therefore **300 × 600 dpi**, not 600 × 600. It documents two-color raster transfer for the QL-800; [Brother's QL-800 download page](https://support.brother.com/g/b/downloadtop.aspx?c=us&lang=en&prod=lpql800eus) says its own Linux drivers support black and white only. The third-party raster path can support black/red output when the correct `DK-22251` media is loaded; the [original driver README](https://github.com/pklaus/brother_ql) names that roll. The QL-800 raster reference also explicitly excludes the zero-raster and TIFF compression commands, so a replacement renderer should continue using the model-aware library rather than constructing generic QL raster data.

For the UI, treat an absent USB device as offline and report explicit status errors when a query fails. Do not show “ready” solely because `/dev/usb/lp0` exists. Red controls should be tied to `62red` media, and high resolution should be described as 300 × 600 dpi along the feed. Physical printing, red-media identification, and persistent power configuration remain unverified.

## Subsequent live status check

After the research pass, we sent only the documented ESC i S status query using nonblocking USB I/O with a three-second deadline. The QL-800 returned a 32-byte reply. The installed driver interpreted it as `Reply to status request`, `Waiting to receive`, `Continuous length tape`, width 62 mm, length 0, and no errors. This verifies status communication and loaded width; it does not verify red media, physical printing, or the Auto Power Off setting. No print command was sent.
