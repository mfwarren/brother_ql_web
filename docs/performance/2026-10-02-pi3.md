# Python versus Rust on the Raspberry Pi

Measured October 2, 2026 on the existing Raspberry Pi 3 Model B Rev 1.2, running 32-bit Raspberry Pi OS. This compares the former production Python/Waitress release `6897ed1` with the deployed Rust/Axum release `7e8b766`. Python is 3.11.2; Rust was built in release mode with Rust 1.94.

The rewrite improves startup, memory use, text previews, and barcode previews. It does not improve every operation. Scaled image previews are slower, QR previews improve modestly, and CSV preparation is about the same.

## Method

The [benchmark script](../../tools/benchmark_backends.py) runs directly on the Pi. It creates separate copies of application data and Python source, starts one benchmark server at a time on loopback port 8026, and alternates Python/Rust ordering over five rounds. The normal production service stays idle and available on port 80. No printer endpoint is called, and both benchmark services must report simulation mode before testing begins.

Each operation has two warm-up requests followed by eight timed requests per round, for 40 observations per backend. HTTP connections are reused. Requests include receiving the complete response and checking its structure. The driver checks that fonts/defaults match and preview dimensions agree. The fixture labels are synthetic, use DejaVu Sans Book, and come from the existing compatibility test generator. The library test uses a private copy of the nine existing saved labels. The result artifact contains timings and resource counters, not label contents.

Startup measures process launch until the configuration API responds, including font discovery. These are process restarts with filesystem caches left intact, not cold boots. Memory comes from Linux `/proc`: RSS is resident memory, PSS apportions shared pages, and VmHWM records the process peak RSS. Each process runs the same workload before the final memory reading.

Temperatures ranged from 55.3 to 64.5 °C. No active throttling flag was set. The Pi already had a historical frequency-capping flag (`0x20000`), unchanged throughout the run. Alternating test order reduces order/temperature effects but does not turn this into a controlled laboratory benchmark.

## Startup and memory

Values below are medians across five independent server processes.

| Metric | Python | Rust | Observed change |
| --- | ---: | ---: | --- |
| Process startup | 2000.12 ms | 45.16 ms | 97.7% lower |
| Idle RSS | 29.91 MiB | 5.39 MiB | 82.0% lower |
| Idle PSS | 24.25 MiB | 3.82 MiB | 84.2% lower |
| RSS after workload | 35.56 MiB | 9.05 MiB | 74.5% lower |
| Peak RSS during workload | 80.88 MiB | 26.21 MiB | 67.6% lower |

The first Python startup took 3.77 seconds; the remaining four took 1.98–2.01 seconds. Rust starts took 39–46 ms. The median startup difference is about 44×. The idle benchmark RSS values do not describe every possible long-running workload.

## Warm HTTP latency

All times are milliseconds. P95 is the nearest-rank 95th percentile of the 40 observations; the samples are grouped within five processes, rather than 40 independent machines.

| Operation | Python median | Rust median | Python P95 | Rust P95 | Observed change |
| --- | ---: | ---: | ---: | ---: | --- |
| Load configuration | 9.27 | 6.57 | 9.79 | 6.70 | 29.1% less time |
| Load saved-label library | 8.76 | 4.42 | 9.18 | 4.48 | 49.5% less time |
| Plain text preview | 25.51 | 11.11 | 25.87 | 11.29 | 56.4% less time |
| Formatted text preview | 31.99 | 16.22 | 45.84 | 16.46 | 49.3% less time |
| QR preview with caption | 153.92 | 143.55 | 173.89 | 144.21 | 6.7% less time |
| Code 128 preview with caption | 47.85 | 18.48 | 48.25 | 18.68 | 61.4% less time |
| Scaled image preview | 94.96 | 125.78 | 104.41 | 126.35 | 32.5% more time |
| High-resolution fixed-label text preview | 732.43 | 309.90 | 750.88 | 311.39 | 57.7% less time |
| Prepare 100 CSV rows | 64.37 | 66.21 | 75.68 | 67.13 | 2.9% more time |

The scaled image fixture is a 32 × 20 pixel PNG enlarged onto 62 mm continuous media. This measures one specific image-upscaling path; it does not establish performance for all uploaded images or PDFs. The high-resolution case uses a fixed 62 × 100 mm label. CSV preparation substitutes and validates 100 drafts; it does not render or print those 100 labels.

## Two simultaneous preview clients

After the sequential workloads, two clients each request 20 formatted-text previews concurrently. Across five rounds, throughput rises from **49.8 to 111.5 previews/second**, approximately **2.24×**. Both clients complete without rejected requests. This measures two-client capacity, not a saturation test or the maximum number of users.

## What still needs work

- Scaled image previews take **32.5% longer**. Median server CPU time also rises from about 96 to 125 ms per request, so this is server computation rather than Wi-Fi latency. Profiling should distinguish resampling from PNG encoding before choosing a fix.
- CSV preparation takes 64.4 versus 66.2 ms, a small 2.9% difference. Treat it as roughly unchanged in this run.
- QR rendering improves by only 6.7%, much less than text rendering.
- Rust's preview PNGs are larger in these fixtures. The scaled image grows from 4,646 to 9,802 bytes; the high-resolution text PNG grows from 19,128 to 56,141 bytes. Encoder choices are another optimization target. These are encoded byte sizes, not changes in label dimensions or printer resolution.

These measurements compare the complete rewrite, including algorithms, libraries, buffering, and PNG encoding. They do not isolate the programming language as the sole cause. They also do not measure browser layout, the frontend preview debounce, font-download network latency, USB transfer, or physical printer speed. A typical simple text preview saves about 14 ms of server time; the tested high-resolution preview saves about 423 ms, which is more likely to be noticeable while editing.

## Reproduce

Keep the previous Python release and its environment available. Choose a new empty work directory; the script refuses to overwrite an existing directory.

```sh
python3 tools/benchmark_backends.py \
  --python-release /opt/label-studio/releases/20260929-7338505 \
  --rust-release /opt/label-studio/releases/20261002-rust-7e8b766 \
  --data /var/lib/label-studio \
  --work /home/matt/label-benchmark-new-run \
  --rounds 5 --samples 8
```

Copy `tools/check_rust_api.py` alongside the script when running outside the checkout. Results are written to `results.json` in the work directory. The [raw recorded results](2026-10-02-pi3-results.json) retain every latency sample, per-process CPU/memory counters, temperatures, test order, and release identifiers. Temporary benchmark servers exited after the test, and the production Rust service remained active.
